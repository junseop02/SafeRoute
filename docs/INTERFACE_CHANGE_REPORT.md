## 1. 문서 목적

본 문서는 SafeRoute 프로젝트의 기존 모델 및 백엔드 인터페이스에서 신규 전국 단위 AI 모델과 경로 추천 정책으로 변경된 내용을 기록하기 위해 작성하였다.

기존 서비스의 개발 목적과 사용자 대상은 유지하면서 데이터 처리 방식, 모델 학습 목표, 도로 링크 점수 제공 방식 및 경로 추천 방식을 개선하였다.

기존 프로젝트 제안서, 백엔드 체크리스트 및 백엔드–모델 인터페이스 합의 문서는 원본 상태로 보존한다.

본 문서는 기존 합의서를 대체하는 확정 문서가 아니며, 신규 구현 내용에 대한 변경 보고서이다. 최종 인터페이스 변경은 팀원 검토 및 승인을 필요로 한다.

## 2. 기존 프로젝트 개발 방향

### 2.1 서비스 목적

SafeRoute는 초보 운전자 및 운전에 어려움을 느끼는 사용자를 대상으로 상대적으로 운전 부담이 낮은 경로를 추천하는 서비스이다.

기존 내비게이션의 최단 거리 및 최소 시간 중심 경로 탐색과 달리 도로 구조, 교차로 특성 및 사고 관련 정보를 고려하여 경로 추천 우선순위를 제공한다.

### 2.2 기존 모델의 한계

기존 경로 회귀 모델은 도로 특성 및 사고 관련 특성을 이용하여 사전에 정의한 규칙 기반 점수를 학습하였다.

이러한 방식은 사람이 설정한 점수 계산 규칙을 모델이 재현하는 구조이다.

높은 결정계수 및 낮은 예측 오차가 실제 운전 난이도나 사고 발생 위험을 정확하게 예측한다는 의미는 아니다.

따라서 신규 모델에서는 사람이 생성한 규칙 기반 점수 대신 실제 수집된 과거 사고다발지역 정보를 이용하여 학습 목표를 구성하였다.

### 2.3 기존 합의 문서 보존

기존 합의 문서에서 제시한 주요 개발 방향은 다음과 같다.

- 천안·아산 지역 중심의 초기 개발
- 도로망과 사고 데이터의 공간적 결합
- 도로 링크 단위 위험도 산출
- 도로 구조 및 교통 관련 특성 활용
- 위험도와 우회 비용을 고려한 경로 추천
- 향후 전국 단위 서비스 확장

신규 구현에서는 전국 도로망과 사고다발지역 폴리곤을 이용하며, 기존 합의 문서의 일부 세부 기준과 다른 방식으로 구현하였다.

기존 문서의 변경 여부는 팀원 협의를 통해 결정한다.

### 6.2 실시간 서비스 처리

신규 서비스는 실시간 경로 조회 과정에서 Python 모델을 직접 실행하지 않는다.

사전에 계산한 전국 도로 링크 점수를 공간 타일 형태로 저장하고, 경로 탐색 시 필요한 타일을 조회한다.

실시간 처리 과정은 다음과 같다.

1. 사용자 출발지 및 도착지 입력
2. 카카오 자동차 경로 API 호출
3. 경로 후보 수집 및 중복 제거
4. 우회 허용 범위 적용
5. 경로 주변 공간 타일 조회
6. 경로와 표준 도로 링크 매칭
7. 매칭된 도로 링크 모델 점수 집계
8. P01 추천 정책 적용
9. 유효 경로 확인
10. 추천 경로 선정 및 사용자 화면 표시

### 6.3 서비스 실행 의존성

신규 서비스의 실시간 실행에는 다음 요소가 필요하다.

- Node.js 실행 환경
- 신규 서비스 JavaScript 및 화면 파일
- 전국 공간 타일
- 공간 타일 manifest
- 추천 정책 설정
- 서비스 인터페이스 설정
- 사용 가능한 카카오 API 키
- 인터넷 연결

Python 가상환경, 원본 SHP 파일 및 모델 학습 파일은 사전 점수 생성이 완료된 신규 실시간 서비스 실행에 필요하지 않다.

| 0 | link_id | String | 표준 도로 링크 ID |
| 1 | coordinates | Array | 경도·위도 순서의 도로 선형 좌표 |
| 2 | hotspot_score | Number | T09 모델 점수 |
| 3 | lanes | Integer | 차로 수 |
| 4 | intersection_nodes_200m | Integer | 링크 선형 기준 200m 이내 교차로 노드 수 |
| 5 | legacy_hotspot_distance_m | Number 또는 Null | 기존 사고다발지역 근접 참고 지표 |
| 6 | part_index | Integer | 복합 선형 링크의 구성 요소 번호 |

hotspot_score는 0~1 범위의 원본 모델 점수이다.

공간 타일 생성 단계에서는 P01 가중치를 적용하지 않는다.

legacy_hotspot_distance_m은 기존 참고 지표를 유지하기 위한 필드이며 P01 경로 추천 점수 계산에는 사용하지 않는다.

### 7.3 복합 선형 및 중복 처리

복합 선형 도로 링크는 구성 요소별로 분리하여 저장한다.

도로 선형의 고유 식별 기준은 다음과 같다.

    link_id + part_index

동일한 도로 선형이 여러 공간 타일에 포함될 수 있으므로 실시간 인덱스 생성 과정에서 중복을 제거한다.

기본 소수점 6자리 좌표 정밀도에서 선형이 소실되는 예외 링크는 소수점 7자리 정밀도를 적용한다.

## 8. 경로 매칭 및 추천 정책

### 8.1 경로와 도로 링크 매칭

| 항목 | 적용 기준 |
|---|---:|
| 공간 인덱스 격자 크기 | 80m |
| 공간 인덱스 여유 범위 | 20m |
| 경로 샘플링 최대 간격 | 25m |
| 최대 도로 매칭 거리 | 18m |
| 방향 유사도 기준 | 절대 코사인 유사도 0.55 이상 |
| 최소 유효 매칭률 | 80% |

도로 매칭은 경로의 샘플링 구간과 주변 도로 선형을 비교하여 수행한다.

방향 비교에서 절대 코사인 유사도를 사용하므로 반대 방향 도로 링크가 매칭될 가능성이 있다.

매칭 결과는 실제 주행 차로를 완전하게 식별한 결과로 해석하지 않는다.

### 8.2 경로 모델 점수 집계

매칭된 경로 구간의 길이를 가중치로 사용하여 도로 링크 모델 점수를 집계한다.

    R = Σ(length_i × hotspot_score_i) / Σ(length_i)

R은 매칭된 구간에 대한 길이 가중 평균 모델 점수이다.

매칭되지 않은 구간에 임의의 0점 또는 안전 점수를 부여하지 않는다.

최소 매칭률을 충족하지 못한 경로는 최종 추천 점수를 제공하지 않는다.

### 8.3 P01 경로 추천 정책

P01 정책은 모델 점수, 좁은 도로 부담 및 교차로 부담을 결합한다.

| 구성 요소 | 기호 | 가중치 |
|---|---|---:|
| 경로 모델 점수 | R | 0.8 |
| 좁은 도로 부담 | N | 0.1 |
| 교차로 부담 | I | 0.1 |

좁은 도로 부담:

    N = 1 - W

W는 매칭된 경로 중 차로 수 2개 이상인 도로의 길이 비율이다.

교차로 부담:

    I = clip(C / 100, 0, 1)

C는 매칭된 도로 링크의 intersection_nodes_200m 특성에 대한 길이 가중 평균이다.

C는 실제 경로에서 통과하는 교차로의 개수를 직접 의미하지 않는다.

최종 경로 부담 점수:

    B = 0.8 × R + 0.1 × N + 0.1 × I

백엔드 제공 점수:

    model_score = 100 × B

사용자 화면 표시 점수:

    Display Score = 100 - model_score

백엔드 model_score는 낮을수록 우선순위가 높으며, 사용자 표시 점수는 높을수록 우선순위가 높다.

### 8.4 추천 정책 선정 근거

천안·아산 수집 경로를 대상으로 여러 가중치 조합을 비교하였다.

공통 우회 허용 배율 2배 조건에서 791개 출발지·도착지 조합을 대상으로 기존 비교 정책과 P01 정책을 비교하였다.

| 비교 항목 | 기존 비교 정책 M02 | 신규 P01 |
|---|---:|---:|
| 평균 경로 모델 점수 | 0.079478 | 0.072111 |
| 평균 큰길 비율 | 0.861144 | 0.847604 |
| 평균 교차로 관련 지표 | 12.960817 | 12.794895 |
| 평균 경로 거리 | 27,082.67m | 27,371.39m |
| 평균 경로 시간 | 1,943.57초 | 1,942.59초 |

P01은 기존 비교 정책 대비 평균 모델 점수가 약 9.27% 감소하였다.

반면 큰길 비율은 약 1.35%p 감소하고 평균 경로 거리는 약 288.72m 증가하였다.

이 결과는 수집된 경로 후보와 모델 점수에 대한 정책 비교 결과이며 실제 사고 감소율을 의미하지 않는다.

### 8.5 P01-v1.1 변경사항

| 항목 | P01-v1.0 | P01-v1.1 |
|---|---:|---:|
| 최소 유효 경로 후보 | 3개 | 2개 |
| 추가 경로 탐색 목표 | 3개 | 3개 |
| 최소 매칭률 | 80% | 80% |
| 모델 점수 가중치 | 80% | 80% |
| 좁은 도로 가중치 | 10% | 10% |
| 교차로 가중치 | 10% | 10% |
| 교차로 정규화 기준 | 100 | 100 |

실제 카카오 API 조회 과정에서 경로 후보가 2개만 제공되는 상황을 확인하였다.

이에 따라 최소 유효 경로 후보를 3개에서 2개로 변경하였다.

변경 과정에서 모델, 모델 학습 데이터, 공간 타일 및 추천 정책 가중치는 변경하지 않았다.

### 8.6 우회 허용 범위

우회 허용 범위는 전체 경로 후보 중 최단 거리 경로를 기준으로 계산한다.

    route_distance ≤ shortest_candidate_distance × detour_cap

| 사용자 선택값 | 적용 기준 |
|---|---|
| 1.5 | 최단 거리의 1.5배 이내 |
| 2 | 최단 거리의 2배 이내 |
| 3 | 최단 거리의 3배 이내 |
| unlimited | 우회 거리 제한 없음 |

현재 화면의 기본 선택값은 2배이다.

### 8.7 최종 추천 조건

다음 조건을 충족하는 경로를 유효 후보로 처리한다.

- 중복 제거된 경로
- 우회 허용 범위 이내의 경로
- 도로 매칭률 80% 이상
- 유효한 모델 및 정책 버전
- 유효한 경로 부담 점수

유효 경로가 2개 이상일 때 추천 경로를 선정한다.

추천 우선순위는 다음과 같다.

1. 경로 부담 점수 오름차순
2. 경로 거리 오름차순
3. 경로 시간 오름차순
4. 경로 ID 오름차순

유효 후보가 부족하면 경로 정보는 표시할 수 있으나 AI 추천 경로는 선정하지 않는다.

현재 추가 경로 탐색은 도로 매칭 이후의 유효 후보 수가 아니라 우회 범위 내 후보 수를 기준으로 종료한다.

따라서 추가 탐색 종료 이후 실제 유효 후보가 부족해질 수 있다.

model_score는 기존 필드명을 유지하지만 신규 P01 정책에 따라 계산한다.

model_raw_risk, model_narrow_burden 및 model_intersection_burden은 신규 추천 정책의 구성 요소를 확인하기 위한 필드이다.

model_hotspot_ratio는 기존 사고다발지역 근접 정보를 제공하는 참고 필드이며 신규 모델의 실제 사고 발생 확률이 아니다.

### 9.6 점수 미제공 처리

최소 도로 매칭률을 충족하지 못한 경로의 다음 필드는 Null로 처리한다.

- model_score
- model_raw_risk
- model_narrow_burden
- model_intersection_burden

매칭률과 매칭 길이 등 확인 가능한 보조 지표는 별도로 제공할 수 있다.

유효하지 않은 모델 점수를 임의로 0점으로 대체하지 않는다.

### 9.7 경로 추천 결과

경로 탐색 결과에는 다음과 같은 정보를 제공한다.

- 경로 후보 목록
- 추천 경로 ID 또는 추천 보류 상태
- 중복 제거된 경로 후보 수
- 최단 후보 거리
- 우회 범위 제외 후보 수
- 최소 경로 수 충족 여부
- 적용 우회 허용 배율
- API 요청 실패 기록
- 모델 버전
- 추천 정책 버전
- 공간 타일 스키마 버전

최소 경로 수 충족 여부와 실제 추천 가능 여부는 구분한다.

우회 범위 내 후보 수가 충분하더라도 도로 매칭률 및 모델 점수 검증 이후 유효 후보가 부족할 수 있다.

## 10. 프론트엔드 인터페이스 변경

### 10.1 사용자 표시 점수

사용자 화면에서는 백엔드 model_score를 다음과 같이 변환한다.

    Display Score = 100 - model_score

표시 명칭은 경로 추천 점수이다.

해당 점수는 P01 정책에 따른 상대적인 추천 우선순위를 의미한다.

실제 사고 발생 확률, 안전 보장 점수 또는 초보 운전자의 실제 운전 능력 평가 점수가 아니다.

### 10.2 주요 표시 항목

- 추천 경로
- 경로 추천 점수
- 예상 이동 거리
- 예상 이동 시간
- 우회 거리 배율
- 도로 매칭률
- 큰길 비율
- 교차로 관련 지표
- 사고다발지역 근접 참고 지표

사고다발지역 근접 참고 지표는 신규 추천 점수 계산에 사용되는 요소와 구분하여 표시한다.

### 10.3 비동기 경로 요청 처리

경로 조회 요청 식별자를 이용하여 이전 요청의 응답이 최신 경로 결과를 덮어쓰지 않도록 처리한다.

최종 모의 UI 환경에서 다음 항목을 검증하였다.

- 이전 경로 요청 성공 응답 무효화
- 이전 경로 요청 실패 응답 무효화
- 이전 요청의 검색 버튼 상태 변경 방지
- 장소 변경에 따른 진행 중 경로 요청 무효화
- 기존 경로 결과 초기화

장소 검색 요청 자체에 대한 별도의 응답 충돌 방지 기능은 추가 개선이 필요하다.

### 10.4 API 키 관리

카카오 REST API 키와 JavaScript 키는 브라우저에서 입력한다.

API 키 입력 필드는 비밀번호 입력 방식으로 구성하였다.

API 키를 브라우저의 localStorage 또는 sessionStorage에 저장하는 방식은 사용하지 않는다.

API 키를 소스코드 및 배포용 ZIP에 포함하지 않는다.

## 14. 제한사항 및 향후 개선

### 14.1 모델 및 데이터 제한사항

- 모델은 과거 사고다발지역 포함 여부를 학습한다.
- 모델 출력값은 보정된 실제 사고 발생 확률이 아니다.
- 사고다발지역 미포함 도로가 안전한 도로임을 의미하지 않는다.
- 사고다발지역 데이터의 사고 유형에 제한이 있다.
- 사고 데이터와 도로망 데이터의 수집 시점에 차이가 있다.
- 초보 운전자의 실제 체감 난이도를 직접 학습하지 않았다.
- 실제 사고 감소 효과를 검증하지 않았다.
- 모든 미관측 지역의 일반화 성능을 보장하지 않는다.
- 사고다발지역 폴리곤의 공식 좌표계 명세는 추가 확인이 필요하다.

### 14.2 추천 정책 제한사항

- P01 가중치는 실제 사용자 평가를 통해 학습된 값이 아니다.
- 큰길 비율은 차로 수 기준이며 실제 도로 폭을 직접 측정한 값이 아니다.
- 교차로 관련 지표는 실제 경로에서 통과하는 교차로 수와 다를 수 있다.
- 모델 점수와 큰길 우선 정책 사이에 상충 관계가 발생할 수 있다.
- 추천 정책 비교 실험은 천안·아산 수집 경로를 중심으로 수행하였다.
- 모델 분류 임계값은 경로 추천 순위 결정에 사용하지 않는다.

### 14.3 서비스 구현 제한사항

- 반대 방향 도로 링크가 매칭될 가능성이 있다.
- 장소 검색 응답 충돌 방지 기능은 추가 개선이 필요하다.
- 지도 범례와 실제 지도 마커 색상이 일치하지 않을 수 있다.
- 추가 경로 탐색 종료 이후 유효 후보가 부족해질 수 있다.
- 경로 정렬 경계 조건의 Python-JavaScript 일치는 추가 확인이 필요하다.
- 신규 UI 자동화 테스트는 모의 DOM 및 지도 SDK 환경에서 수행하였다.
- 모든 실제 브라우저 환경의 정상 작동을 보장하지 않는다.
- 독립 배포 폴더 및 별도 PC 실행 검증은 미완료 상태이다.
- 신규 Python 환경에서의 전체 의존성 재설치 검증은 미완료 상태이다.

### 14.4 향후 개선 방향

- 초보 운전자 대상 실제 주행 평가
- 운전자 체감 난이도 데이터 수집
- 교통사고 데이터 유형 확대
- 사고 및 도로망 데이터 수집 시점 정합성 개선
- 실제 도로 폭 및 차로 변경 특성 반영
- 회전 및 교차로 통과 난이도 반영
- 도로 매칭 정확도 개선
- 유효 경로 수 기반 추가 탐색 개선
- 장소 검색 비동기 요청 관리 개선
